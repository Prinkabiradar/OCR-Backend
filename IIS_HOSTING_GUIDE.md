# IIS Hosting Guide

This guide is for hosting the OCR application on a Windows Server with IIS.

It covers:

- Backend publish and IIS deployment
- Frontend production build
- Chrome setup required for PDF formatting
- App Pool restart and verification
- Common issues when PDF changes do not reflect on the server

## 1. Server Requirements

Install these on the Windows Server:

- IIS
- ASP.NET Core Hosting Bundle for the same .NET version used by the backend
- Google Chrome
- Node.js, only if you build the frontend directly on the server

After installing the ASP.NET Core Hosting Bundle, restart IIS:

```powershell
iisreset
```

## 2. Install Chrome for PDF Generation

The PDF generator uses Chrome headless rendering so the PDF can match the editor formatting.

Install Google Chrome on the server and confirm this file exists:

```text
C:\Program Files\Google\Chrome\Application\chrome.exe
```

If Chrome is installed somewhere else, set this environment variable for the IIS site or server:

```text
CHROME_BIN=C:\Program Files\Google\Chrome\Application\chrome.exe
```

After setting the environment variable, recycle the IIS Application Pool.

## 3. Publish the Backend

From the project machine, go to the backend folder:

```bash
cd "../OCR-Backend"
dotnet publish -c Release -o publish
```

This creates the deployable backend files inside:

```text
OCR-Backend/publish
```

Upload the full contents of this `publish` folder to the backend folder configured in IIS.

Important: replace the old hosted files. Make sure the new `OCR-BACKEND.dll` is copied to the server.

## 4. Build the Frontend

From the frontend folder:

```bash
npm install
npm run build
```

Deploy the generated production build folder to the frontend site configured in IIS.

Depending on the Angular/Ionic configuration, the output folder is usually one of these:

```text
dist/
www/
```

Use the folder that is generated by your project build.

## 5. IIS Backend Setup

In IIS Manager:

1. Create or select the backend site.
2. Point the physical path to the backend published folder.
3. Set the Application Pool to `No Managed Code`.
4. Confirm the site has the correct port or hostname.
5. Confirm the backend folder has read/execute permission for the App Pool identity.

Recommended App Pool settings:

```text
.NET CLR Version: No Managed Code
Managed Pipeline Mode: Integrated
Enable 32-Bit Applications: False
Start Mode: AlwaysRunning
```

Recycle the backend Application Pool after deployment.

## 6. IIS Frontend Setup

In IIS Manager:

1. Create or select the frontend site.
2. Point the physical path to the frontend production build folder.
3. Confirm the frontend API URL points to the hosted backend URL.
4. Restart or recycle the frontend site.

For Angular routing, make sure URL rewrite is configured so browser refresh works on deep links.

Example `web.config` for frontend SPA routing:

```xml
<?xml version="1.0" encoding="utf-8"?>
<configuration>
  <system.webServer>
    <rewrite>
      <rules>
        <rule name="Angular Routes" stopProcessing="true">
          <match url=".*" />
          <conditions logicalGrouping="MatchAll">
            <add input="{REQUEST_FILENAME}" matchType="IsFile" negate="true" />
            <add input="{REQUEST_FILENAME}" matchType="IsDirectory" negate="true" />
          </conditions>
          <action type="Rewrite" url="/" />
        </rule>
      </rules>
    </rewrite>
  </system.webServer>
</configuration>
```

## 7. Restart IIS After Deployment

After replacing backend files, recycle the backend Application Pool.

You can also restart IIS from an Administrator PowerShell:

```powershell
iisreset
```

## 8. Verify PDF Formatting on Server

Generate a PDF from the hosted application and check the backend logs.

Expected success log:

```text
[DocumentPdfGenerator] PDF generated with Chrome HTML renderer.
```

This means the server is using the new editor-style PDF renderer.

If you see this log:

```text
[DocumentPdfGenerator] Chrome not found. Falling back to QuestPDF renderer.
```

then Chrome is missing or IIS cannot find it. Install Chrome, set `CHROME_BIN` if needed, and recycle the App Pool.

## 9. If PDF Changes Are Not Reflecting

Check these in order:

1. Confirm you ran a fresh backend publish:

```bash
dotnet publish -c Release -o publish
```

2. Confirm the new published files were copied to the IIS backend folder.

3. Confirm the backend App Pool was recycled after copying files.

4. Confirm Chrome is installed at:

```text
C:\Program Files\Google\Chrome\Application\chrome.exe
```

5. Confirm the backend logs show:

```text
[DocumentPdfGenerator] PDF generated with Chrome HTML renderer.
```

6. Clear browser cache or test in a private/incognito window.

7. Confirm the frontend is pointing to the correct hosted backend API URL.

## 10. Quick Deployment Checklist

Backend:

```bash
cd "../OCR-Backend"
dotnet publish -c Release -o publish
```

Frontend:

```bash
npm install
npm run build
```

Server:

```text
Copy backend publish files to IIS backend folder
Copy frontend build files to IIS frontend folder
Install Chrome
Recycle backend App Pool
Recycle frontend site/App Pool
Generate PDF and check logs
```

## 11. Important Note About PDF Matching

The editor and PDF will match only when the backend uses the Chrome HTML renderer.

If Chrome is unavailable on IIS, the backend uses the fallback PDF renderer, and the PDF may not match the editor formatting exactly.
